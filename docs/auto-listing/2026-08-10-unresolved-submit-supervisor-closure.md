# 未确认提交被任务层误判完成：根因与闭环

## 生产证据

- 原运行 `20260809-214041` 在人工复核第 8 个目标为精确标题 0 条后，安全重试并确认发布成功。
- 第 9、10 个目标随后确认发布成功。
- 第 11 个目标点击发布后没有收到成功信号；商品列表精确查重被“商品类目错放”信息预警遮挡，因此仍属于 `final_publish_state_uncertain`。
- 发布批次正确停止，但任务编排仍把 task 记为 done 并以退出码 0 结束；监督器看到飞书仍为 pending 后启动 full flow，错误地从第 1 个目标重建。
- 错误重建在最终提交点击前被终止，耐久提交证据为 `not_attempted`，未造成重复发布。

## 根因

发布动作层与任务完成层使用了不同完成语义。动作层把未确认提交写入失败 manifest 并打开熔断器，但任务层允许函数正常返回；监督器只看子进程退出码和飞书 pending 状态，没有在转入 full flow 前再次检查当前批次是否仍存在未解决的发布边界。

同时，精确标题查重只识别质量分和属性优化两类弹窗，未识别纯信息性质的“类目错放预警”，导致无法完成第二次稳定查重。

## 根治

1. 监督器在任何成功子进程准备转入 full flow 前，复扫当前飞书批次的 publish manifest。
2. 若仍有未被批次完成规则接受的 failed 条目，且无法构造安全 resume job，则直接停止，禁止 full flow、禁止重放更早目标。
3. 如果人工复核许可已存在且可以构造 resume job，仍优先继续精确 resume，不进入 full flow。
4. 商品列表查重仅识别同时包含“检测到您有”“商品类目错放”“逾期未改会被平台下架”“建议使用推荐类目”“发起申诉”的信息预警；优先 Escape，否则只允许唯一关闭控件，绝不点击“使用推荐类目”或“发起申诉”。
5. 弹窗关闭后必须验证消失，才允许继续精确标题查询。
6. 历史不确定结果若实时精确标题查询返回正数，使用独立正向对账动作：先校验店铺、标题、canonical identity 和 manifest identity，再归档原 result/manifest/查询证据，最后原子写为 `published + list_verified`；该路径永不点击发布。
7. 控制器新增“成功但不完整 manifest”恢复来源：即使 task 曾被错误写为 done，只要当前飞书批次身份一致且 20 个目标尚有缺口，就只生成缺口目标的 `startStep=published` resume job。

## 验证

- 成功子进程 + 飞书 pending + 未解决发布边界 + 无 resume：禁止 full flow。
- 同场景有安全 resume：允许继续 resume。
- 类目错放预警严格文本分类、唯一关闭控件选择和无安全关闭控件拒绝均有测试。
- 正向对账仅接受 `共N条 (N>0)`，并验证 result/manifest 双重身份；不完整 manifest 选择器只返回未被批次完成规则覆盖的目标。
- 全量规则审计继续覆盖标题固定后缀中的 `*` 保留、OTC 类目隔离、无坐标点击、身份绑定和提交边界。
