# 步骤 02：本地千问商品场景规划

## 目标

把步骤 01 已审核并固化的商品文案交给本机 Ollama `qwen3.6:35b-a3b`，一次生成 5 个互不重复的消费者时刻。千问只负责消费时刻、环境、氛围和商品互动关系；包装事实、海报文案、配色、构图、人物策略、艺术字和质量门禁均由程序固定规则控制。

## 动作与规则

- [qwen-scene-planner.ts](../../../src/autolist/qwen-scene-planner.ts)
- [scene-word-docs.ts](../../../src/autolist/scene-word-docs.ts)

## 唯一语义来源

### 来源规则

商品名称与语义只来自当前飞书记录。可展示主标题、副标题和卖点的唯一来源是飞书 `主图主标题`、`主图副标题`、`主图卖点` 经步骤 01 审核并固化的完整商品文案；场景规划固定使用本地 `qwen3.6:35b-a3b`。千问不得查看商品图片、猜测包装、改写文案或新增功效、适用人群、成分、认证、规格及品牌口号。

## 本地模型契约

类目提示词数量是固定业务规则：

- 医疗器械：5 段提示词。
- 非处方药：5 段提示词。
- 保健食品：5 段提示词。

1. 唯一模型为本地 `qwen3.6:35b-a3b`，默认地址 `http://127.0.0.1:11434`。
2. 请求使用 Ollama `/api/generate`、`stream=false`、`think=false` 和固定 JSON schema。
3. 返回值必须恰好包含 5 个对象；每个对象只有 `consumerMoment`、`environment`、`mood`、`interaction` 四个字段。结构或内容越界时，本地最多纠错重试三次，仍不合格则失败关闭。
4. 五个场景的消费者时刻、环境和互动方式必须各不相同。
5. 出现医院医生、症状伤口、治疗结果、前后对比、未批准人群、其他商品、促销信息或新增可读文字时整组失败，不进入付费生图。

## 程序边界

程序把千问四字段组装为 5 个有边界的场景段落，并按轮次追加固定人物策略：

1. 临床信息图：只允许手部或使用部位局部，不出现完整脸部。
2. 自然生活：最多一位自然人物，人物不得大于完整商品组。
3. 科技原理：不出现完整人物。
4. 极简英雄：不出现人物、面部或手部。
5. 使用方法：只允许手部和使用部位局部步骤，不出现完整脸部。

每个场景段落都必须再次锁定：完整参考商品组原样、成组、最大且最清晰；包装数量、文字、比例、颜色和标识只以参考图为准；禁止症状、医院、治疗结果、前后对比、其他商品、促销元素和额外可读文字。

## Word 输出

每份 Word 只能包含两段：

```text
第一段：已审核的完整商品文案
第二段：当前轮经过程序边界组装的本地千问场景
```

五份 Word、场景规划模型版本、商品文案摘要和业务规则指纹必须绑定。任一摘要或版本变化后，旧场景、旧 Word、旧付费槽位和旧恢复产物不得静默复用。

## 失败条件

- 本地 Ollama 不可访问或未安装指定模型。
- JSON schema 不满足、字段为空、字段过长或不是恰好 5 个场景。
- 五个场景重复。
- 场景越过程序内容边界。
- 场景摘要与当前飞书商品文案不一致。
- Word 不是恰好两段或混入旧场景。

以上任一情况均在付费生图前失败关闭。
